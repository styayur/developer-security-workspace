# rusqlite 0.41 integer compatibility

The 0.37 to 0.41 binding update removes direct `usize` SQL conversion and makes progress-handler installation/reset fallible. Use checked `usize` to SQLite signed-64-bit conversion and checked integer row decoding for SARIF staging/reference indices, finding counts, navigation, dashboard aggregates, pagination and lifecycle counts. Negative, fractional, textual, null or unrepresentable integer values fail through the existing database-error path. No table, column, migration version or persisted JSON schema changes.

Lifecycle increments are checked and encoded before durable commit. A bad count must roll back the finding transaction. Scan-history reads propagate corrupt-row errors instead of silently discarding those rows. Streaming imports handle progress-hook installation/reset errors and still attempt owned temporary-table cleanup and detach after failures. Cancellation/transaction semantics remain covered by the existing tests.

Actual local checks pass: 62 core tests, checked integer boundary tests, strict all-target Clippy with warnings denied and Windows desktop-feature compilation. Four pre-existing external-tool/performance tests remain explicitly ignored in the ordinary core run; this is not a claim that they ran here. A new persistence regression closes its own synthetic database, copies the checkpointed file as a backup, reopens it, checks finding/lifecycle values, rejects negative stored counts, checks failed overflow rollback and verifies the original file bytes remain unchanged while corrupting only the backup. Separate SQLite tests reject invalid storage types and exercise platform-specific representability bounds.

No real user database, scanner output or private session is opened or uploaded. No irreversible data migration is introduced. The unchanged CI dependency/license security gate, both core platform jobs, desktop tests, CodeForge and unsigned installer candidate must still pass for the exact PR head. The local `cargo deny` command was unavailable; its fixed-version CI job is required before merge and is not replaced by compilation success. No advisory exception or license allowance was added.
